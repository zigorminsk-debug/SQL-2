Категории ожиданий и что с ними делать

Дисковый ввод-вывод — 2,5 ч
Ожидание чтения/записи страниц с диска. Либо медленная подсистема, либо нехватка памяти буферного пула (данные не помещаются), либо сканирования больших таблиц.
  • Проверить задержки диска (менее 10–20 мс на чтение — норма)
  • Сопоставить PLE с эталоном, проверить планы и лишние чтения, затем память и диск
  • Найти запросы с большими logical/physical reads и оптимизировать
  • Проверить фрагментацию индексов и статистику
CPU и планировщик — 1,7 ч
Запросы ждут доступа к процессору или связаны с параллелизмом. Часто означает нехватку вычислительных ресурсов либо неоптимальные параллельные планы.
  • Проверить загрузку CPU процессом SQL Server и ОС в целом
  • Настроить MAXDOP и cost threshold for parallelism
  • Найти самые дорогие запросы по CPU и оптимизировать их
Сеть и клиентские приложения — 34,8 мин
Сервер отдал данные, но клиент медленно их читает (ASYNC_NETWORK_IO и подобные) — узкое место на стороне приложения.
  • Проверить, нет ли выбора «всей таблицы» в приложение
  • Оптимизировать обработку результатов на стороне клиента
  • Уменьшить объём возвращаемых данных (TOP, пагинация)
Журнал транзакций — 30,4 мин
Ожидание записи в журнал транзакций (WRITELOG и др.) — медленный диск под файлы .ldf или слишком частые мелкие коммиты.
  • Разместить .ldf на быстром диске (SSD)
  • Проверить частоту транзакций, объём журнала и рост файлов
  • Проверить, делаются ли резервные копии журнала (модель FULL)
Блокировки — 17,4 мин
Ожидание блокировок (LOCK) — одни транзакции мешают другим. Типично для длинных транзакций и последовательного изменения «горячих» строк.
  • Сначала проверьте режим блокировок и совместимость конфигурации 1С. RCSI влияет только на READ COMMITTED, не устраняет REPEATABLE READ/SERIALIZABLE и конфликты писателей. Перевод в управляемый режим требует доработки и тестирования кода 1С. Оцените место под версии строк в tempdb (при ADR — PVS), длинные транзакции и окно обслуживания; согласуйте изменение с DBA. Не включайте принудительный откат рабочих транзакций.
  • Сократить длительность транзакций, проверять индексы WHERE/JOIN
  • Избегать изменения ключей и «горячих» таблиц длинными транзакциями
Память (гранты) — 13,0 мин
Ожидание памяти для выполнения запросов (RESOURCE_SEMAPHORE и др.) — запросам не хватает памяти на сортировки/хеширования.
  • Проверить max server memory и PLE
  • Найти запросы с большими грантами памяти и оптимизировать их
  • Проверить оценку кардинальности/устаревшую статистику
Защёлки (latch) — 8,7 мин
Внутренние ожидания структур данных SQL Server. Высокие значения часто связаны с tempdb (PFS/GAM/SGAM) или с большим объёмом модификаций страниц.

Приложение: методика и права

Источники данных (только чтение)

Инструмент выполняет только SELECT к системным представлениям:

  • sys.dm_os_wait_stats, sys.dm_os_performance_counters, sys.dm_os_sys_info, sys.dm_os_ring_buffers
  • sys.dm_exec_requests / sessions / query_stats, sys.dm_exec_sql_text, sys.dm_exec_query_plan
  • sys.dm_db_missing_index_*, sys.dm_db_index_physical_stats, sys.dm_db_stats_properties
  • sys.databases, sys.master_files, sys.dm_io_virtual_file_stats, sys.dm_os_volume_stats
  • msdb.dbo.backupset, msdb.dbo.sysjobhistory, system_health (deadlocks), sp_readerrorlog

Требуемые права

  • VIEW SERVER STATE — основной объём данных;
  • VIEW ANY DATABASE + чтение пользовательских баз — индексы/статистика;
  • чтение msdb — бэкапы и задания;
  • securityadmin или права на sp_readerrorlog — журнал ошибок.

Недостающие права не ломают отчёт — недоступные проверки отмечаются в сводке. Инструмент ничего не изменяет на сервере.
