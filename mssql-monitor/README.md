# MS SQL Monitor — контроль, диагностика и оптимизация MS SQL Server

Программа для контроля работы **Microsoft SQL Server**: мониторинг потребления ресурсов,
скорости обработки запросов, настроек сервера — с автоматическими рекомендациями по
устранению проблем и оптимизации. Формирует подробный **HTML-отчёт** с графиками загрузки
за сутки и детальным разбором причин замедлений. Поставляется в виде одного EXE-файла с GUI.

> Программа **ничего не изменяет** на SQL Server: все данные собираются только
> чтением (SELECT) системных представлений (DMV). Изменения — только в вашей локальной базе мониторинга.

## Возможности

| Направление | Что делает |
|---|---|
| Ресурсы | CPU (SQL и системы), память буферного пула, ввод-вывод (задержки чтения/записи), tempdb, сессии |
| Скорость обработки | запросов/с (Batch Requests/sec), транзакций/с, компиляции/рекомпиляции, Page Life Expectancy, Buffer cache hit ratio |
| Суточный мониторинг | фоновый опрос каждые N секунд (по умолчанию 60), накопление в локальной SQLite, графики за 24 ч (и более), авто-отчёт по завершении |
| Причины замедлений | автоматическое выделение «окон замедления» на графике, и для каждого окна — доминирующие ожидания, цепочки блокировок и долгие запросы именно этого периода |
| Ожидания (waits) | разбор по категориям с пояснениями и действиями: CPU, диски, блокировки, память, журнал транзакций, сеть/клиент, репликация |
| Запросы | топ по CPU / длительности / чтениям, множество планов у одного запроса (parameter sniffing), неявные преобразования типов, проливы в tempdb |
| Блокировки и deadlock | живые цепочки, история за период, «виновники» с текстом запроса, разбор графов взаимоблокировок из system_health |
| Индексы и статистика | отсутствующие индексы (с готовыми CREATE INDEX), фрагментация (REBUILD/REORGANIZE), устаревшая статистика, неиспользуемые индексы |
| Базы данных | размеры, модель восстановления, совместимость, VLF, заполненность журнала, RCSI, AUTO_SHRINK/CLOSE, тома и свободное место, бэкапы, задания SQL Agent |
| Настройки сервера | max server memory, MAXDOP, cost threshold, optimize for ad hoc и др. — текущее vs рекомендуемое |
| Рекомендации | 30+ правил с уровнями Критично/Важно/Рекомендация, объяснением «что это значит», «как исправить» и готовым T-SQL |
| Отчёт | один самодостаточный HTML-файл (работает офлайн, открывается в любом браузере), оценка «здоровья» 0–100, навигация, печать |

Есть **демо-режим** (кнопка «Демо-отчёт»): показывает, как выглядит отчёт, на виртуальном
сервере с реалистичными проблемами — подключение к реальному SQL Server не требуется.

## Быстрый старт (готовый EXE)

Сборка EXE выполняется на Windows (PyInstaller не умеет кросс-компиляцию), поэтому в комплекте
**одно-щёлчковый скрипт**:

1. Установите Python 3.10–3.12 (https://www.python.org/downloads/), при установке отметьте
   **«Add python.exe to PATH»**.
2. Дважды щёлкните **`build.bat`** (находясь в папке проекта).
3. Заберите готовый файл **`dist\MSSQLMonitor.exe`** — это один самодостаточный файл,
   Python на целевом компьютере уже не нужен.

Варианты:
- `build.bat cli` — дополнительно консольная версия `MSSQLMonitorCLI.exe` для Task Scheduler
  (суточный мониторинг + отчёт без открытия окна).
- Нет желания ставить Python? Используйте **GitHub Actions**: создайте репозиторий, загрузите
  файлы проекта, вкладка *Actions → Build Windows EXE → Run workflow* — готовый EXE будет в
  Artifacts (см. `.github/workflows/build-windows.yml`).

Запуск из исходников без сборки: `python app.py`.

## Подключение к SQL Server

| Поле | Комментарий |
|---|---|
| Сервер | `SRV01` или именованный инстанс `SRV01\SQL2022`; порт по умолчанию 1433 |
| Аутентификация | Windows (доменная) или логин/пароль SQL Server |
| Шифрование | TLS опционально; «доверять сертификату» включено по умолчанию (обычный случай самоподписанных сертификатов) |

**Драйверы** — ставятся оба, работает любой:
- **pyodbc** — используется, если в системе есть «ODBC Driver 17/18 for SQL Server»
  (обычно уже есть на машинах с SSMS; иначе: https://learn.microsoft.com/sql/connect/odbc/download-odbc-driver-for-sql-server);
- **pymssql** (FreeTDS) — встроен в EXE, внешние драйверы не нужны — используется как запасной.

### Права на сервере

Для полного отчёта достаточно связки:
```sql
CREATE LOGIN [DOMAIN\monitor_user] FROM WINDOWS;
ALTER SERVER ROLE sysadmin ADD MEMBER [DOMAIN\monitor_user];   -- или минимально:
GRANT VIEW SERVER STATE TO [DOMAIN\monitor_user];               -- основной объём данных
GRANT VIEW ANY DATABASE TO [DOMAIN\monitor_user];               -- + чтение пользовательских БД
```
- статистика индексов/таблиц — нужны права чтения в пользовательских базах;
- бэкапы и задания — чтение `msdb`;
- журнал ошибок — `securityadmin` или право на `sp_readerrorlog`.

Недостающие права **не ломают** отчёт — недоступные проверки просто помечаются в сводке.

## Как пользоваться

### Суточный мониторинг
1. Вкладка **«Подключение»** — укажите сервер, «Проверить подключение».
2. Вкладка **«Мониторинг»** — интервал (обычно 60 с), длительность (24 ч), «▶ Начать мониторинг».
3. Живые показатели (CPU, запросы/с, PLE, tempdb, блокировки) обновляются в реальном времени.
4. По завершении (или кнопкой на вкладке «Диагностика и отчёт») будет сформирован отчёт:
   графики за сутки + автоматические **окна замедления** с разбором причин.

Мониторинг переживает перезапуск программы: данные копятся в `data\monitor.db` (локально),
а отчёт можно строить за любой накопленный период (1–168 ч или всё).

### Отчёт-снимок прямо сейчас
Кнопка **«📄 Сформировать отчёт»** — глубокая диагностика на текущий момент
(без суточного мониторинга графики будут пропущены, всё остальное — полное).

### CLI (Task Scheduler), например на 03:00 каждую ночь
```
MSSQLMonitorCLI.exe --cli --server SRV01 --auth windows --hours 24 --interval 60
:: только отчёт без мониторинга:
MSSQLMonitorCLI.exe --cli --server SRV01 --auth sql --user sa --password *** --skip-monitor
```
Отчёты сохраняются в папку `reports\`, журнал — в `logs\`.

## Что анализируется (кратко)

- **Ожидания** `sys.dm_os_wait_stats` — signal wait %, доминирующие категории, 40+ типов с пояснениями;
- **Запросы** `sys.dm_exec_query_stats/plans` — топ по CPU/длительности/чтениям, неявные
  преобразования, SpillToTempDb, дубли планов; `sys.dm_exec_requests` — текущие и блокирующие;
- **Индексы** — `dm_db_missing_index_*` (готовый DDL), `dm_db_index_physical_stats` (фрагментация),
  `dm_db_stats_properties` (устаревшая статистика), `dm_db_index_usage_stats` (неиспользуемые);
- **Базы/файлы/диски** — `sys.databases`, `master_files`, `dm_io_virtual_file_stats`
  (задержки по файлам), `dm_os_volume_stats` (свободное место), `dm_db_log_space_usage`,
  `dm_db_log_info` (VLF);
- **Операции** — `msdb.dbo.backupset` (свежесть бэкапов), `sysjobhistory` (сбои заданий),
  system_health (deadlock-графы), `sp_readerrorlog` (I/O stall 833, автоприращения, память);
- **Настройки** — `sys.configurations`, `dm_os_sys_info`, `dm_server_services`, Query Store, трассировочные флаги.

Все рекомендации — рекомендательный характер: перед применением T-SQL из отчёта
проверяйте его на тестовой среде.

|---|---|
| `app.py` | GUI (tkinter), конфигурация, CLI, сборка отчёта |

Требования: Windows 7+ / Windows Server 2012+ для EXE; SQL Server 2012–2022 (включая Express);
для старых версий (2008 R2) часть проверок деградирует корректно.

## Частые вопросы

- **«Не удалось подключиться»** — проверьте, что на SQL Server включён TCP/IP
  (SQL Server Configuration Manager → Protocols), порт открыт, для именованных инстансов
  работает служба SQL Browser (UDP 1434). Ошибка сертификата → включите «доверять сертификату».
- **Часть разделов пустая** — не хватает прав (см. выше), список недоступных проверок виден в сводке отчёта.
- **Фрагментация считается долго** — на больших БД отключите её галочкой перед формированием отчёта.
- **Где данные мониторинга?** — `data\` рядом с EXE (или `%USERPROFILE%\MSSQLMonitor`, если папка только для чтения). Хранение — 14 суток.
